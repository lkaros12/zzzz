# 작업: 별장 → 하단 도시 씬 이동 (한 방향)

## 원칙 (AGENTS.md 와 같다)
1. Think Before Coding — 명세가 모호하거나 코드와 안 맞으면 추측하지 말고 멈추고 보고한다.
2. Simplicity First — 최소 코드. 새 런타임 클래스는 씬 이동 1개만 허용.
3. Surgical Changes — 관련 줄만. 재포맷·무관한 변경 금지.
4. Goal-Driven Execution — 완료 기준별로 무엇이 확인하는지 남긴다.
- UTF-8, 한글 주석("왜"), **perl 편집 금지**. Unity 에디터 조작·커밋 금지 (컴파일·테스트는 메인).
- **토큰 절약**: `V01SceneBuilder.cs`(5,400줄) 전체를 읽지 마라. `CreateEstate` 의 대문 부분(4939~4946줄 근처)과 `BuildInternal`, 자기검사 진입점만 본다.

## 목적
별장 대문 밖으로 걸어 나가면 하단 도시 씬으로 넘어간다. 플레이어 상태는 이어진다.
**한 방향이다 (사용자 결정): 도시에서 별장으로 돌아가는 길은 만들지 않는다.**

## 만들 것
1. **새 런타임 스크립트** `Assets/_Game/Scripts/World/SceneExit.cs` — 트리거 콜라이더에 플레이어가 들어오면 대상 씬을 불러온다.
   - 필드: 대상 씬 이름, 도착 지점 이름(대상 씬 안의 빈 오브젝트 이름).
   - 불러오기 전에 **플레이어 상태만** 정적 보관함에 담고, 새 씬에서 플레이어가 생긴 뒤 복원한다.
     넘길 것: 체력·허기·탈수·피곤함·스태미나, 인벤토리, 장비, 퀵슬롯, 부상·출혈, 치료 중 회복 상태는 버려도 됨, 게임 시각(GameClock).
     - 기존 `SaveSystem` 의 플레이어 직렬화 코드를 재사용할 수 있으면 재사용 (파일에 쓰지 말고 메모리로). 막히면 멈추고 보고.
   - 도착 위치: 도착 지점 오브젝트 위치로 CharacterController 를 끄고 옮긴 뒤 켠다.
   - 이동 중 화면: 기존 HUD 안내 텍스트에 "이동 중..." 한 줄이면 충분. 페이드·로딩 화면 없음.
2. **별장 빌더**: 대문(x 23.8~30.2, z -30.1) 바깥 남쪽에 트리거 `Exit_ToCity` (대문 폭, 깊이 2m, 대문에서 3m 밖). 바닥에 눈에 띄는 표시(색 판) 하나.
3. **도시 빌더**: 도착 지점 `Arrive_FromEstate` = 기존 시작 위치 (빈 오브젝트). 돌아가는 트리거는 없다.
4. 두 씬을 `EditorBuildSettings.scenes` 에 등록 (없으면 추가, 중복 금지). 빌더 실행 시 보장.
5. 별장 씬에서 저장/불러오기(`SaveSystem`)는 지금처럼 동작. 도시 씬은 저장 대상 아님 — 도시에서 저장 키를 눌러도 별장 세이브를 덮어쓰지 않게 막는다 (가장 짧은 방법).

## 하지 말 것 (제외 범위)
- 도시 → 별장 복귀 (사용자 결정으로 제외). 따라서 별장 월드 상태 보존도 불필요.
- 도시 좀비·아이템 배치, 로딩 화면, 페이드, 비동기 로딩, 도시 저장.

## 자기검사
- 별장 `Tools/V0.1/Self Check`: `Exit_ToCity` 트리거가 대문 바깥에 있고 isTrigger, 대상 씬 이름이 빌드 설정에 있다, 마당에서 트리거까지 NavMesh 경로가 이어진다 (걸어서 닿는다).
- 도시 `Tools/V0.1/Check Hadan Pilot`: `Arrive_FromEstate` 가 있고 건물 콜라이더와 안 겹친다, 도시에 별장으로 가는 SceneExit 가 없다.
- 에디트 모드에서 가능한 상태 이동 검사: 플레이어 상태를 보관함에 담았다가 다른 플레이어 오브젝트에 복원하면 체력·인벤토리 개수·부상·출혈이 같다.
