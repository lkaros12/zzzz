# 수정: 16 원인 확정 — 문 NavMesh 실패는 닫힌 문 장애물의 에디트 모드 카빙 (검사 문제)

원칙(AGENTS.md): 최소 코드, 관련 줄만. UTF-8·한글 주석, perl 금지, Unity 조작·커밋 금지. 게임 동작(닫힌 문이 길을 깎는 것)은 **바꾸지 않는다**.

## 메인 실험으로 확정한 원인
- 문 오브젝트를 모두 끄고 `V01SceneBuilder.BuildNavMesh()` → 문 중심 NavMesh 있음 (거리 0.00).
- 문은 켜고 **문짝 `NavMeshObstacle`(carve=True) 만 끄고** 굽기 → 문 중심 NavMesh 있음.
- 장애물을 다시 켜도 같은 호출 안에서는 아직 있음 → 카빙은 **에디터 틱이 지나야** 적용된다.
- 즉 `Check Hadan Pilot` 은 빌드와 **별도 메뉴 호출**이라, 그 사이에 닫힌 문 장애물이 문 자리를 깎아 둔 상태에서 검사한다 → "문 중심 NavMesh 0/20", "문 앞→꼭대기 0채" 는 **검사 방법이 틀린 것**이다. (게임에서는 닫힌 문이 막고, 열면 뚫리는 의도된 동작.)

## 고칠 것
1. 문 중심 NavMesh 검사와 문 앞→꼭대기 경로 검사를 **문이 열린 상태를 반영**하게: 가장 짧은 방법을 고른다 — (a) 이 두 검사를 빌드 메뉴 안 `BuildNavMesh()` 직후(카빙 전)에 실행해 결과를 `BuildingFloors` 등 씬 컴포넌트의 직렬화 필드에 기록하고 Check 가 그 값을 확인, 또는 (b) Check 안에서 문 장애물을 끄고 NavMesh 를 다시 구운 뒤 검사하고 원상복구(시간 +15초). 어느 쪽인지와 이유 보고. 별장 Self Check 가 같은 문제를 어떻게 피하는지(같은 호출 안에서 굽고 바로 검사?) 참고해 일관되게.
2. **법선 실패**가 여전히 남아 있다 (`층·외벽·계단·지붕 면의 법선이 올바르다` FAIL). 검사가 실패하는 첫 3개 면(메쉬 이름·서브메쉬·면 중심·법선·기대 방향)을 로그로 남기게 하고, 원인이 코드면 고친다. 원인을 모르면 로그만 넣고 보고 (검사 완화 금지).
3. 구간 진단 로그는 유지.
