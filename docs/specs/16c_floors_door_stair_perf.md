## 메인 실측 (빌드 로그)

Check Hadan Pilot 실패 7건: 법선 / "1층 외벽 메쉬가 문 중심을 막지 않는다" / "외벽 바깥면에 기존 외관 텍스처와 UV" / "문 앞→꼭대기 경로 0채" / 삼각형 300k / GameObject 20k / Data 파일 수(첫 빌드, 무시).

## 원인 측정 (건물 `Building_1387626559`, 문 (-99.55,1.2,383.57), 계단 Floor_0/Stair_0)
- NavMesh: **계단 바닥→꼭대기 PathComplete, 계단 꼭대기→2층 바닥 PathComplete, 2층 가장자리→2층 중심 PathComplete.**
- **끊김 1 — 문**: 문 밖 1.5m → 문 안 1.5m 경로 PathPartial, 문 한가운데(-99.3,0.1,383.7)에서 멈춤. 자기검사 "외벽 메쉬가 문 중심을 막는다" 실패와 같은 원인으로 보임 → **1층 외벽(`WallSpans`)이 문이 있는 변에서 실제로 구멍을 내지 않거나 다른 변을 자른다.** 문 위치의 변 인덱스·거리 계산 확인.
- **끊김 2 — 계단 입구**: 1층 안쪽 → 계단 첫 단(-97.78,0.5,379.16) PathPartial, (-98.2,0.1,380.0) 에서 멈춤. 계단 메쉬 가장 낮은 정점 y=0.0 인데 1층 바닥판 윗면은 약 0.1~0.2 (바닥 두께 0.2). 계단 옆벽/막힌 면이 입구 쪽을 막거나 첫 단이 바닥 속에 묻힌 것으로 보임 → **계단 첫 단을 바닥판 윗면 기준으로 올리고, 계단 입구(아래쪽 끝) 방향에는 벽이 없게.** 옆벽은 계단 양옆만.
- **성능 — 결정적**: 재생 PlayerLoop 9.49ms (16 전 4.15). `PreLateUpdate.ScriptRunBehaviourLateUpdate` 6.54ms. 원인: **`WallSegment` 11,746개가 전부 매 프레임 `LateUpdate`** (`WallSegment.cs:168`, 흐림이 없어도 호출). BuildingFloors·WallFader 를 꺼도 6.2~6.6ms 그대로였다.

## 고칠 것
1. **WallSegment 쉬는 동안 LateUpdate 끄기**: 알파가 1(완전 불투명)이고 요청이 없으면 `enabled = false`, `RequestFade`(또는 흐림 요청 경로)가 오면 `enabled = true`. 별장 동작(실내 벽 흐림·지붕)은 그대로여야 한다. 호출 순서(요청이 LateUpdate 전에 오는지) 확인.
2. **문 구멍**: 위 끊김 1. 자기검사 "문 중심을 막지 않는다" 와 경로가 통과하게.
3. **계단 입구**: 위 끊김 2. 첫 단 높이 ≤ 바닥 윗면 + 0.25, 입구 쪽 막힘 없음.
4. **법선 실패·외관 UV 실패**: 원인을 찾아 고친다 (새 외벽 두께 메쉬의 안쪽 면/옆면·끝단 면 감김, UV 검사 대상이 바깥면만인지). 검사가 틀렸으면 검사를 새 구조에 맞게 — 어느 쪽인지 보고.
5. **한도 (메인 결정)**: GameObject 한도 25,000, 고유 삼각형 한도 500,000 으로 올린다 (실제 병목은 LateUpdate 였고 그리기 호출 152 로 괜찮음). 대신 PlayerLoop 가 목표 — 메인이 잰다.
6. `CheckBuildingPaths` 가 끊김 1·2 를 잡으면 통과해야 한다 (고정 시드 5채 이상 문 앞→꼭대기).
